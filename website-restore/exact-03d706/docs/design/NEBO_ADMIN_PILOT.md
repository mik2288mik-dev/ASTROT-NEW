# NEBO admin design pilot

User-approved reference: ten four-screen boards supplied September 7, 2026. Foreground product layer moves over the personal page; collapsed/middle/expanded are positions, scrolling inside expanded is not a fourth position. Both themes. No mockup people, dates, prices, fake scores or invented product capabilities.

This pilot overrides old visual instructions only while a server-authorized administrator explicitly selects `nebo-v2`. Classic remains default for all accounts. Existing calculators, ownership, auth, consent gates, RuStore verification and content generation rules remain authoritative. In particular, do not fabricate transit facts or split forecasts into unimplemented data categories to match decorative mockup text.

## Included implementation

- Server-authenticated admin switch in Settings. Session-local emergency return, DB preference revision control, additive preference table, cleanup through user foreign key.
- Dashboard and own natal presentation using existing services/controllers; two-surface gestures, keyboard alternatives, reduced motion, native Back, Telegram host swipe coordination.
- Shared menu hub, fixed five-item navigation, light/dark styles, 34 illustration tiles including 12 zodiac signs from the user boards.
- Natal per-chart/per-content-version reading place, existing explanatory sheet and paywall return context.

## Deliberate boundaries

Saved-person natal, compatibility, matrix and most service detail screens retain existing working flows. Onboarding and paywall reuse existing functional components under a scoped skin; this is not a claim that all 40 reference states have been rebuilt. No friends/messenger/pet forecasts, placeholder balances, fake progress percentages or unlimited questions. Export/rendered source images are not calculation data.

## Safety and verification

`NEBO_ADMIN_DESIGN_PREVIEW_DISABLED=1` fails closed on server. Design preferences never grant Premium. Missing DB migration returns 503 and keeps classic. Migrate before attempting the switch. Full implementation signoff requires native/Telegram gesture and actual purchase testing; browser/CI checks are not device confirmation. Compare only approved same-size state fixtures, then check smaller screens and large text separately.

The one-time integration script only edits an explicit list and asserts unique anchors. The branch-only validation workflow must pass type checking, focused tests, migration and production build before publishing its integration commit. Do not publish a partial tree or claim a successful deploy from source presence alone.
