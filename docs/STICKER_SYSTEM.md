# Динамическая система стикеров

Стикеры (маскоты `cat_/capy_`) выбираются по **жёстким правилам размещения** и обновляются
**2 раза в сутки** (не на каждый заход). Каталог — это данные, а не код: добавить сотни
стикеров можно, просто разложив корректно названные файлы, без правок компонентов.

## Как это устроено

```
public/stickers/*.webp            маскоты  (имя = животное_образ_поза_настроение)
public/stickers/objects/*.webp    предметы (имя = предмет[_вариант])
public/stickers/catalog.overrides.json   необязательные точечные уточнения

lib/stickers/parseName.ts   имя файла → теги
lib/stickers/rules.ts       теги → где уместен + допустимые позиции (дефолты)
lib/stickers/select.ts      чистый выбор: seed → набор {стикер, позиция}, лимит на экран
pages/api/stickers/catalog.ts   сканирует папки в рантайме → отдаёт каталог (кэш 60с)
services/stickerService.ts      загрузка каталога на клиенте (+ localStorage)
components/stickers/StickerScreen.tsx   провайдер экрана + <StickerSlot surface=…/>
styles/stickers.css             слой стикеров, позиции, гарантия «не обрезать»
```

Поток: `StickerScreen` при монтировании берёт seed из **временно́го ключа** (дата + половина
суток), грузит каталог и делает **один** выбор на весь экран (соблюдая общий лимит 3). Каждый
`<StickerSlot surface=…/>` рисует стикер своего блока. В пределах 12-часового окна раскладка
не меняется (сколько ни заходи); на границе окна — обновляется.

## Как добавить свой стикер (без разработки)

1. **Вырежи фон** и сохрани `.webp` с прозрачностью (как остальные).
2. **Назови по схеме** и положи в папку:
   - Маскот → `public/stickers/`, имя `животное_образ_поза_настроение.webp`
     (животное: `cat`/`capy`; поза: `pawup pawdown wave sit run peek stand point`;
     настроение: `happy calm hype thinking cheer chill surprise`).
     Пример: `capy_palm_sit_chill.webp`.
   - Предмет → `public/stickers/objects/`, имя `предмет[_вариант].webp`.
     Пример: `palm.webp`, `slippers.webp`, `fan.webp`, `lamp_green.webp`.
3. Готово. Каталог подхватит файл на следующем открытии (кэш API — 60 сек). Теги маскота
   берутся из имени; предмет получает спокойный дефолт (`calm/happy/chill`, все блоки).

### Когда нужна одна строка в overrides (не обязательно)

`public/stickers/catalog.overrides.json` — точечно поменять поведение стикера. Ключ = имя файла
без расширения **или** образ/предмет (подействует на все `palm*`). Любое поле необязательно:

```json
{
  "palm": { "moods": ["chill", "happy"], "surfaces": ["hero", "moon"] },
  "fan":  { "surfaces": ["hero"], "positions": ["bottom-right-peek"] },
  "cat_skate_pawup_hype": { "exclude": true }
}
```

Поля: `type`, `moods`, `surfaces` (`hero`/`moon`/`sphere`/`feed`), `positions`, `exclude`.

## Жёсткие правила размещения

1. **Общий лимит на весь экран** — максимум **3** стикера суммарно по всем карточкам
   (`totalMax`), один счётчик на весь рендер, не на карточку.
2. **Один маскот на карточку, максимум.** Никогда два маскота вместе. Реализовано: на блок
   выбирается ровно один маскот или ноль.
3. **Никаких одиночных предметов.** Ставятся только маскоты (у них предмет уже в кадре как
   часть композиции). Пустая карточка лучше случайного предмета.
4. **Стикеры не перекрывают текст.** У каждого блока — текстовая зона и ОТДЕЛЬНАЯ безопасная
   зона под стикер. Позиции (`lib/stickers/rules.ts` → `SURFACE_POSITIONS`) привязаны к зонам
   без текста: `hero-scene` (верхняя «сцена» карточки-героя, над copy/do-dont), `moon-gutter`
   (правый отступ карточки луны — там `padding-right` резервирует место), `corner-peek` (угол).
5. **Тематика + настроение.** Каждый блок в `STICKER_REQUESTS` задаёт и `moods`, и `themes`
   (`drink/read/cozy/gift/tech/active/study`). Фильтр идёт по обоим. Луна = спокойная «ночная»
   тематика (`drink/read/cozy`), техника/актив исключены — никаких наушников/геймпадов.
6. **Смена 2 раза в сутки, не на каждый заход.** Выбор детерминирован временны́м ключом
   `getStickerTimeKey()` = московская дата + половина суток (`am`/`pm`). 10 открытий в одном
   полудне → одна и та же раскладка; меняется на границе 12-часового окна. (Тот же принцип
   детерминированного выбора по временному ключу, что и у fallback-текстов.)

## Гарантия «не обрезать» (overflow)

Позиции `*-peek` выступают за край карточки отрицательными отступами. Карточка-хост помечается
классом `has-stickers`, который в `styles/stickers.css` ставит `overflow: visible` — выступ не
режется. Текстура/скругление карточки при этом остаются (фон обрезается по `border-radius`,
а не по `overflow`). Слой стикеров — `pointer-events: none`, клики по карточке не перехватывает.

## Координация с параллельным дизайн-агентом (Codex)

Этот модуль подключается в `views/Dashboard.tsx` (экран «Сегодня»), который дизайн-агент
правит параллельно. Точки стыка:

- В `Dashboard.tsx` статические `<img>` стикеров (moon-маскот, notebook/coffee) **заменены** на
  `<StickerScreen>` + `<StickerSlot/>`. **Не возвращать** статические стикеры в карточки —
  их рисует слот.
- Вся раскладка стикеров живёт в **`styles/stickers.css`** (не в `globals.css`). Классы
  изолированы префиксом `.sticker*` / `.has-stickers` — стилям `.home-*` не мешают.
- Карточке, куда добавляется стикер, нужен класс `has-stickers` (даёт `overflow: visible`).
  Если дизайн переверстает карточку — сохранить этот класс на хосте стикера.
