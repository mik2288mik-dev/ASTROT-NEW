# Active decisions — Onboarding V1

This file overrides any earlier exploratory mockup or visual-direction document.

## Product flow currently fixed

- One onboarding flow with Personal/Zodiac branching on screen 3.
- Birth data is requested only after the Personal path is chosen.
- Zodiac users may enter the Zodiac section without completing personal birth data.
- Native UI owns copy, buttons, fields, progress, legal links and accessibility labels.
- Runtime integration waits for the published Personal Forecast V3 branch.

## Visual direction is NOT fixed

The following directions are obsolete and must not be treated as current requirements:

- bright editorial illustration as a mandatory style;
- paper layers / cut-paper depth;
- magazine print texture / halftone as a mandatory treatment;
- cat or capybara as required onboarding characters;
- milk-white base as a locked onboarding system;
- blanket bans or requirements for photography, 3D, beige, dark palettes or any other visual medium.

No onboarding artwork may be generated, implemented or registered as final production art from those old assumptions.

Before visual production:

1. Audit the latest approved application screens and the final Personal Forecast V3 UI after it is published.
2. Separate what is genuinely current from archived experiments and old design documents.
3. Prepare several complete onboarding visual directions using the same flow and native copy.
4. Show rendered results to the product owner for selection.
5. Only the selected direction may become an asset specification.

Until then, implementation may use neutral layout placeholders and a swappable asset resolver, but must not encode a visual style as a product decision.
