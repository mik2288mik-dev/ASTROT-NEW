# Security Hardening (Docker + CI)

## Что изменено

- Сборка и установка зависимостей вынесены в отдельные build-стадии Docker.
- Runtime-контейнер теперь минимальный:
  - без `npm install` при старте;
  - без `python3/make/g++` (toolchain только на этапе сборки);
  - запуск от непривилегированного пользователя `nextjs`.
- Включен `Next.js standalone` режим, чтобы в прод-образ попадали только runtime-файлы.
- Добавлен `HEALTHCHECK` в Docker-образ.
- Добавлен CI (`.github/workflows/ci.yml`) с:
  - `lint`, `test`, `build`;
  - security-гейтом по `critical` уязвимостям;
  - артефактом полного `npm audit` отчета.

## Важно про Swiss Ephemeris

Натальные расчеты **не отключались** и не заменялись.

`swisseph-v2` продолжает работать с вашими эфемеридами (`ephe/*.se1`), а hardening касается только безопасного процесса сборки/деплоя.

## Почему в audit может оставаться high у `tar`

Цепочка `swisseph-v2 -> node-gyp -> ... -> tar` используется в основном на этапе установки/компиляции нативного модуля.

На момент изменений для части этой цепочки может не быть автоматического fix в npm.  
Поэтому мы:

1. не собираем зависимости в runtime;
2. блокируем CI только по `critical`;
3. сохраняем полный отчет аудита для контроля динамики.
